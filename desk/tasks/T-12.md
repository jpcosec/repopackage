# T-12 - Add Dependency Direction Guardrail to Design

## Traits (Composición)
`[Diseño] | [System] | [Python]`

## Explanation
The current codebase has an inverted dependency: `repopackage.workflow` (domain layer) imports from `repopackage.cli.models` and `repopackage.cli.engines`. This violates the layered architecture defined in the class diagram. A guardrail must be added to the design corpus and enforced by `rp eval audit` so future Executors cannot repeat this mistake.

## Reference
- `desk/design/cli_class_diagram.puml`
- `desk/design/cli_system_spec.md`
- `desk/pills/PILL-12.md`

## What to Fix / Implement
- Add a guardrail pill documenting the dependency direction rule: `cli/ → workflow/ → engines/ → models/`. `workflow/` must never import from `cli/`.
- Add import graph check to `rp eval audit` that fails if any module under `repopackage.workflow` imports from `repopackage.cli`.

## How to Do It (Suggested)
1. Create `desk/pills/PILL-13.md` as a `guardrail` pill documenting the rule.
2. Implement import graph scan in `rp eval audit` using `ast` or `importlib` to detect violations.
3. Make the check blocking (fail the audit if violated).
